LLD 02 — Bucket Matcher

Places each employee in exactly one primary bucket by comparing their profile vector against existing bucket profiles. Creates new buckets from unmatched clusters.

Plain English

Takes each employee's embedded profile (built from their title, department, and all responsibility chunks) and assigns them to the right role group — a "bucket". It runs an approximate nearest-neighbour search against all existing bucket profiles and scores each candidate using a formula that combines vector similarity, responsibility overlap, and title keyword match.

There are three outcomes based on how confident the match is:

  • High confidence — automatically assigned, no review needed.
  • Medium confidence — provisionally assigned and queued for an admin to confirm.
  • Low / no match — added to an "unbucketed pool" to wait for enough similar people to accumulate.

When the pool is big enough, NewBucketJob runs a clustering algorithm, creates a draft bucket per cluster, and uses an LLM to name each cluster from its members' job titles. Even single-person clusters get their own bucket.

There is also secondary bucket assignment — if an employee scores above a lower threshold on a second bucket, they are quietly tagged as secondary. This comes into play later when the question router widens its search beyond the primary bucket.

3 · Components

Profile Vector Builder

Responsibility: Produce a single dense embedding for the employee combining raw_title, department, and all responsibility chunks.

Interface: buildProfileVector(user_id) → Float32Array

Reads: tenant_users, user_responsibilities

Writes: tenant_users.profile_vector

Idempotency: Re-run produces identical vector for same inputs; safe to retry.

Failure handling: Embedding API failure → retry with backoff; job fails and requeues if all retries exhausted.

ANN Candidate Search

Responsibility: Query pgvector HNSW on bucket_embeddings; return all buckets above BUCKET_CANDIDATE_THRESHOLD (not fixed top-k).

Interface: findCandidateBuckets(profileVector, tenantId) → BucketCandidate[]

Reads: bucket_embeddings via pgvector HNSW index

Writes: None

Idempotency: Read-only.

Failure handling: pgvector unavailable → job fails and requeues.

Scoring Function

Responsibility: Compute a combined match score for each candidate bucket.

Formula: score = (profile_cosine × W_cos) + (responsibility_overlap × W_resp) + (title_keyword_boost × W_title)

Responsibility overlap = share of user's responsibility chunks matching a responsibility node in that bucket. Weights are config values.

Interface: scoreCandidates(user_id, candidates: BucketCandidate[]) → ScoredBucket[]

Reads: kg_nodes, kg_edges for bucket responsibility membership

Writes: None

Confidence Router

Responsibility: Route based on top score: high → auto-assign; medium → provisional + queue review; low / no candidate → unbucketed pool.

Interface: routeByConfidence(user_id, scores: ScoredBucket[]) → void

Reads: Config thresholds

Writes: user_bucket_map (on assign); admin review queue (on provisional); unbucketed pool table (on low)

Failure handling: Any write failure → job requeues; upsert semantics prevent duplicates.

NewBucketJob

Responsibility: When the unbucketed pool settles post-onboarding (then nightly), run HDBSCAN on profile vectors; create a draft bucket per cluster; use LLM to name each bucket from member titles; singletons get their own draft bucket.

Interface: NewBucketJob.run(tenant_id) → {created: number, draft_bucket_ids: string[]}

Reads: Unbucketed pool, tenant_users.profile_vector

Writes: buckets (status=draft), user_bucket_map, bucket_embeddings

Idempotency: Idempotent within a run window; re-running with same pool produces same clusters (deterministic seed).

Failure handling: LLM naming failure → bucket saved with auto-generated placeholder name; admin can rename.

Secondary Bucket Assigner

Responsibility: If an employee has strong overlap with a second bucket (above SECONDARY_BUCKET_OVERLAP_THRESHOLD), assign it as secondary. Secondary buckets are searchable by Question Router but not shown on dashboard by default.

Interface: assignSecondaryBucket(user_id, scores: ScoredBucket[]) → void

Reads: Scored bucket list from Scoring Function

Writes: user_bucket_map (role=secondary)

BucketAssigned Emitter

Responsibility: Upsert user_bucket_map and emit BucketAssigned(user_id, bucket_id) to trigger bundle build and gap analysis.

Interface: emitBucketAssigned(user_id, bucket_id, method) → void

Reads: None

Writes: user_bucket_map, Kafka topic / event bus

Idempotency: Upsert; duplicate emit is safe (consumers are idempotent).

10 · Edge Cases & Open Questions

Edge Cases
  • All employees for a new tenant score low confidence → entire tenant lands in unbucketed pool; NewBucketJob runs after onboarding and creates draft buckets for the whole org.
  • Singleton cluster from HDBSCAN → still gets a draft bucket; one-person bucket is valid and will accumulate a dedicated widget bundle.
  • Bucket name collision (LLM generates duplicate name) → append a disambiguating suffix; admin can rename before activation.
  • Secondary bucket same as primary (score ties) → dedup in Secondary Bucket Assigner; never assign the same bucket in both roles.
Open Questions
  • When should a provisional bucket assignment auto-promote to confirmed without admin review (e.g., after N days with no dispute)?
  • Should bucket version increment trigger immediate bundle rebuild for all members or only invalidate cache?
